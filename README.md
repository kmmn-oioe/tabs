# 🎸tabs

音声ファイルやYouTubeのリンクから、曲のギターtab譜(タブ譜)を自動生成するWindowsデスクトップアプリです。

## 機能

- 🎵 音声ファイル(wav / mp3 / flac / m4a / ogg など)を読み込んで解析
- 📺 YouTube URL から音声をダウンロードして解析
- 🎚️ (任意)Demucs によるギターパート分離 → 精度アップ
- 🎼 音程検出は Spotify の **basic-pitch**
- 🎸 チューニング選択(レギュラー / ドロップD / 半音下 / Open G)、カポ位置指定
- ⏱ BPMの自動推定とグリッド原点(オフセット)合わせ
- 🖐 コード単位の弦・フレット割当(運指の連続性を考慮)
- 💾 タブ譜(.txt)と MIDI(.mid)で保存

## セットアップ(Windows)

Python **3.11** をインストールしてから(basic-pitch が依存する TensorFlow の都合上、3.12以降は非対応):

```bat
py -3.11 -m venv .venv
.venv\Scripts\pip install -r requirements.txt
tabs.bat
```

※ `py -3.11` が見つからない場合は `winget install --id Python.Python.3.11` で入れてください。

### ギターパート分離を使う場合(推奨・容量大)

```bat
py -3 -m pip install demucs torch
```

※ torch は数GBダウンロードされます。CPUでも動作しますが処理に時間がかかります。

## 使い方

1. `tabs.bat` を起動
2. 音声ファイルを「参照…」で選ぶか、YouTube URL を貼り付け
3. チューニングやBPMを設定して「タブ譜を生成」
4. 結果を確認し「タブを保存 (.txt)」

## exe 化(配布用)

```bat
py -3 -m pip install pyinstaller
pyinstaller --name tabs --noconsole --collect-all basic_pitch ^
  --collect-all pretty_midi --collect-all yt_dlp main.py
```

生成物は `dist/tabs/tabs.exe` です。

## 仕組み

```
音声 / YouTube
   └─ yt-dlp で音声取得(YouTubeの場合)
   └─ Demucs でギターステム分離(任意)
   └─ basic-pitch でノート検出(時刻・音程・信頼度)
   └─ チューニングに割り当ててtab譜テキスト化
```

## 制限

- 採譜と運指の最適化は推定です。原曲の複数のギターを完全に分離・再現するものではありません
- アコースティック/クリーンギター向けです。激しいディストーションや高速演奏は精度が落ちます



## 演奏しやすいTABの生成

「演奏難易度」で、同時発音数と押弦の広さを選べます。

| 難易度 | 最大同時発音数 | 押弦フレット差 | セーハ |
| --- | --- | --- | --- |
| 初級 | 3音 | 3 | 使わない |
| 標準（既定） | 4音 | 4 | 使用可 |
| 上級 | 6音 | 5 | 使用可 |

同じ弦に同時に複数音を割り当てず、開放弦を除いた押弦幅、標準的な
648mmスケールでの指の広がり、4本の指で押さえられるかを評価します。
セーハは最も低い押弦フレットでの人差し指1本を想定します。
複数の運指候補からフレーズ全体の移動コストを比較し、速い箇所の大きな
ポジション移動を避けます。候補数を制限した探索なので、厳密な最適解や
すべての奏者にとっての演奏可能性を保証するものではありません。

難しい和音は最高音を旋律候補として優先し、次に最低音、信頼度の高い内声を
残します。MIDI・MusicXMLにも同じ省略とグリッド上の発音タイミングを反映します。
リード／リズム分割時は、それぞれを別のギターパートとして最適化します。

現時点では各発音位置で前の押弦を解放する簡略モデルです。前の音の長さは
次の発音位置までに短縮されるため、独立した持続声部、レガート、スライド、
ベンドなどの奏法は再現しません。旋律追跡を使ってもすべての誤検出を
除去できるわけではありません。

開発用の検証（仮想環境を有効化して実行）:

```sh
python -m unittest discover -s tests -v
```

### リズムギターをコード伴奏にする

「リード / コード伴奏に分けて生成」にチェックを入れてください。
リードは旋律のTAB、リズムは **C → G → Am → F** のようなコード切替として出力します。

- リードは発音の近い音を候補として、信頼度・長さ・前後の音程移動から旋律の経路を
  選びます。「リード音域の目安」は弱い補助条件で、低い旋律も追跡します。
- リズムは音声の打楽器的な成分を弱め、クロマ（12音の強さ）と低音成分から推定します。
  隣接音へのスペクトル漏れを抑え、曲全体の調性を弱い補助情報として使います。
- コード切替はBPMとオフセットに沿った拍ごとの候補を、前後のつながりでまとめて選びます。
  旧方式の固定2拍・4拍の区切りの途中でも切り替えられます。
  「コード安定性」は既定で2拍。1拍は細かな変化を許し、4拍は同じコードの継続を優先します。
  拍の間の切替やテンポの揺れへの追従は未対応です。
- 音声解析を利用できない場合は、従来の検出ノートによるコード推定へ切り替えます。
  この場合はTAB内にも代替方式を使ったことを表示します。
- 同じコードが続く区間はまとめ、次の切替まで同じ押さえ方を保持します。
  TABの `~~` は音を伸ばす区間です。ストロークパターンの自動生成は行いません。
- コード進行には小節・拍と開始／終了秒を表示します（4/4拍子を想定）。
  コード名はカポ使用時も実際に鳴る音の名前、フレット番号はカポからの相対位置です。
- メジャー、マイナー、7、maj7、m7、dim、sus2、sus4、パワーコード（5）を対象にします。
  単音しかない区間や無音、十分に説明できない区間は `N.C.`（コードなし）として扱います。
- 難易度とチューニングに合う押さえ方を選びます。初級のセブンスコードは、
  ルート・3度・7度を残し5度を省略します。押さえ方が見つからない場合も `N.C.` にします。
- MIDIには保持する和音、MusicXMLには同じ和音とコード記号を出力します。

音声の打楽器成分の抑制はギターの音源分離とは異なります。歌や鍵盤などの混入、
旋律と伴奏の重なり、転回形、拍推定のずれなどで誤ることがあり、原曲どおりの採譜を保証しません。
音源分離を使う場合、Demucsの6ステムモデルでは `guitar.wav` を解析します。
標準4ステムモデルへの代替時は `other.wav` を使うため、ギター以外の音も含まれます。
どちらも原曲のリード／リズムという役割ごとの分離を保証するものではありません。
