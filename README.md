# 🎸tabs

音声ファイルやYouTubeのリンクから、曲のギターtab譜(タブ譜)を自動生成するWindowsデスクトップアプリです。

## 再生位置の表示

TAB生成後にプレイヤーの再生ボタンを押すと、赤い縦バーと薄黄色のセルが現在位置を示します。
TAB生成後の再生対象は既定で「元の音源」です。「再生音源」で元音源と分離後音源を
選択でき、選んだ1ファイルだけを再生します。分離していない場合は元音源のみです。
切替時は前の再生を止め、再生位置を引き継ぎます。一時停止中の切替では再生を始めません。
解析開始時と結果の読込時も、それまでのプレビューを停止します。

「再生位置を追従」を有効にすると、該当する小節と横方向の位置へ自動スクロールします。
分割生成では「追従パート」でリード／リズムのどちらを中心に表示するか選べます。
「追従パート」は譜面の表示先の選択です。リードだけの音源を追加再生するものではありません。
分離後の音源には複数のギターや、分離しきれなかった他の楽器の音が含まれる場合があります。

一時停止ではその位置を保持し、停止ボタンは先頭へ戻ります。スライダーで移動した位置にも
バーが追従します。自動追従を外すと、表示位置を固定したまま譜面を確認できます。
同期には生成時のBPM・グリッドオフセットを使用し、自動推定値も反映します。
設定欄を後から編集した値は、次回の生成から使われます。

バーやハイライトは表示用で、コピー・保存するTABテキストには入りません。
フォントの拡大やスクロールに対応しますが、弦行や列数の構造を変更した部分では
誤った位置を示さないよう同期表示を停止します。別の音声を読み込んだ場合も、
その音声でTABを生成してから同期表示が有効になります。

## 機能

- 🎵 音声ファイル(wav / mp3 / flac / m4a / ogg など)を読み込んで解析
- 📺 YouTube URL から音声をダウンロードして解析
- 🎚️ (任意)Demucs によるギターパート分離 → 精度アップ
- 🎼 音程検出は Spotify の **basic-pitch**
- 🎸 チューニング選択(レギュラー / ドロップD / 半音下 / Open G)、カポ位置指定
- ⏱ BPMの自動推定とグリッド原点(オフセット)合わせ
- 🖐 コード単位の弦・フレット割当(運指の連続性を考慮)
- 💾 タブ譜(.txt)と MIDI(.mid)で保存

## セットアップ(Windows)

Python **3.11** をインストールしてから(basic-pitch が依存する TensorFlow の都合上、3.12以降は非対応):

```bat
py -3.11 -m venv .venv
.venv\Scripts\pip install -r requirements.txt
tabs.bat
```

※ `py -3.11` が見つからない場合は `winget install --id Python.Python.3.11` で入れてください。

### ギターパート分離を使う場合(推奨・容量大)

```bat
py -3 -m pip install demucs torch
```

※ torch は数GBダウンロードされます。CPUでも動作しますが処理に時間がかかります。

## 使い方

1. `tabs.bat` を起動
2. 音声ファイルを「参照…」で選ぶか、YouTube URL を貼り付け
3. チューニングやBPMを設定して「タブ譜を生成」
4. 結果を確認し「タブを保存 (.txt)」

採譜の精度を実曲の正解TABと比較する開発用テストは
[比較テストの説明と実行方法](benchmarks/README.md)を参照してください。
音程候補・リード選別後・最終出力を別々に測定できます。

### コード付きTAB譜をPDFで保存

TAB生成後、「PDFで保存」を押すと、弦の線とフレット番号によるTAB譜を保存します。
上段に推定コード名、下段に拍を表示し、小節番号・BPM・チューニング・カポも記載します。
リード／リズムを分割した場合は、それぞれ別のPDFとして保存できます。
リード側にも伴奏と同じコード進行を表示します。休符区間にフレット番号は追加しません。
コード名は実音、フレット番号はカポからの相対位置です。`~` はコードを伸ばす区間です。
段の先頭の括弧付きコード名は、前の段から同じコードが続いていることを示します。

MuseScoreや楽譜用フォントの追加インストールは不要です。
PDFは生成時の運指データを使用します（画面上のTABテキストの手編集は反映しません）。
更新前の生成結果を使っている場合は、一度TABを生成し直してからPDF保存してください。
MusicXMLの保存は引き続き通常の五線譜形式です。

## exe 化(配布用)

```bat
py -3 -m pip install pyinstaller
pyinstaller --name tabs --noconsole --collect-all basic_pitch ^
  --collect-all pretty_midi --collect-all yt_dlp main.py
```

生成物は `dist/tabs/tabs.exe` です。

## 仕組み

```
音声 / YouTube
   └─ yt-dlp で音声取得(YouTubeの場合)
   └─ Demucs でギターステム分離(任意)
   └─ basic-pitch でノート検出(時刻・音程・信頼度)
   └─ チューニングに割り当ててtab譜テキスト化
```

## 制限

- 採譜と運指の最適化は推定です。原曲の複数のギターを完全に分離・再現するものではありません
- アコースティック/クリーンギター向けです。激しいディストーションや高速演奏は精度が落ちます



## 演奏しやすいTABの生成

「演奏難易度」で、同時発音数と押弦の広さを選べます。

| 難易度 | 最大同時発音数 | 押弦フレット差 | セーハ |
| --- | --- | --- | --- |
| 初級 | 3音 | 3 | 使わない |
| 標準（既定） | 4音 | 4 | 使用可 |
| 上級 | 6音 | 5 | 使用可 |

同じ弦に同時に複数音を割り当てず、開放弦を除いた押弦幅、標準的な
648mmスケールでの指の広がり、4本の指で押さえられるかを評価します。
セーハは最も低い押弦フレットでの人差し指1本を想定します。
複数の運指候補からフレーズ全体の移動コストを比較し、速い箇所の大きな
ポジション移動を避けます。候補数を制限した探索なので、厳密な最適解や
すべての奏者にとっての演奏可能性を保証するものではありません。

難しい和音は最高音を旋律候補として優先し、次に最低音、信頼度の高い内声を
残します。MIDI・MusicXMLにも同じ省略とグリッド上の発音タイミングを反映します。
リード／リズム分割時は、それぞれを別のギターパートとして最適化します。

現時点では各発音位置で前の押弦を解放する簡略モデルです。前の音の長さは
次の発音位置までに短縮されるため、独立した持続声部、レガート、スライド、
ベンドなどの奏法は再現しません。旋律追跡を使ってもすべての誤検出を
除去できるわけではありません。

開発用の検証（仮想環境を有効化して実行）:

```sh
python -m unittest discover -s tests -v
```

### リズムギターをコード伴奏にする

「リード / コード伴奏に分けて生成」にチェックを入れてください。
リードは旋律のTAB、リズムは **C → G → Am → F** のようなコード切替として出力します。

- リードは発音の近い音を候補として、信頼度・長さ・前後の音程移動から旋律の経路を
  選びます。「リード音域の目安」は弱い補助条件で、低い旋律も追跡します。
- リズムは音声の打楽器的な成分を弱め、クロマ（12音の強さ）と低音成分から推定します。
  隣接音へのスペクトル漏れを抑え、曲全体の調性を弱い補助情報として使います。
- コード切替はBPMとオフセットに沿った拍ごとの候補を、前後のつながりでまとめて選びます。
  複数拍にまたがる和音と持続時間を一緒に評価し、アルペジオの各音、短い付加音、
  判断が弱い1拍をそれぞれ別コードや `N.C.` として出しすぎないようにします。
  複数拍の平均だけで本当の切替を隠さないよう、各拍との矛盾も評価します。
  実際の無音は休符として残し、根拠の強い短いコード変更は保持します。
  旧方式の固定2拍・4拍の区切りの途中でも切り替えられます。
  「コード安定性」は既定で2拍。1拍は細かな変化を許し、4拍は同じコードの継続を優先します。
  強制的にその拍数ごとに切り替える設定ではありません。安定性を上げすぎると本当の切替も
  まとめてしまう可能性があります。切替が減ったことだけでは正しい進行と判断できません。
  拍の間の切替やテンポの揺れへの追従は未対応です。
- 音声解析を利用できない場合は、従来の検出ノートによるコード推定へ切り替えます。
  この場合はTAB内にも代替方式を使ったことを表示します。
- 同じコードが続く区間はまとめ、次の切替まで同じ押さえ方を保持します。
  TABの `~~` は音を伸ばす区間です。ストロークパターンの自動生成は行いません。
- コード進行には小節・拍と開始／終了秒を表示します（4/4拍子を想定）。
  コード名はカポ使用時も実際に鳴る音の名前、フレット番号はカポからの相対位置です。
- メジャー、マイナー、7、maj7、m7、dim、sus2、sus4、パワーコード（5）を対象にします。
  単音しかない区間や無音、十分に説明できない区間は `N.C.`（コードなし）として扱います。
- 難易度とチューニングに合う押さえ方を選びます。初級のセブンスコードは、
  ルート・3度・7度を残し5度を省略します。押さえ方が見つからない場合も `N.C.` にします。
- MIDIには保持する和音、MusicXMLには同じ和音とコード記号を出力します。

音声の打楽器成分の抑制はギターの音源分離とは異なります。歌や鍵盤などの混入、
旋律と伴奏の重なり、転回形、拍推定のずれなどで誤ることがあり、原曲どおりの採譜を保証しません。
音源分離を使う場合、Demucsの6ステムモデルでは `guitar.wav` を解析します。
標準4ステムモデルへの代替時は `other.wav` を使うため、ギター以外の音も含まれます。
どちらも原曲のリード／リズムという役割ごとの分離を保証するものではありません。

### リードが鳴っていないイントロを休符にする

リズムだけの音からも旋律らしい並びを選べてしまうため、旋律追跡だけでは
「別のリードギターが実際に存在する」とは判定できません。
「コード打音をリードから除外」（既定で有効）は、短い時間に重なって鳴った
3音以上のコード／ストロークをリード候補から除外します。
リード自体がコードを弾く場合や、伴奏と同時に鳴るリードを拾いたい場合は解除できます。
アルペジオや同じタイミングに重なる複数のギターの識別は、なお不確実です。

入りの時刻が分かる場合は「リード開始（秒・0=自動）」を指定してください。
たとえば冒頭約11秒がリズムだけなら `11` にします。その時刻より前に始まる音を
リードへ入れず、開始位置を曲の先頭へ詰めないままTAB・MIDI・MusicXMLへ出力します。
グリッドへの丸めも開始指定より前へ戻さないようにします。MusicXMLは記譜グリッドの
都合で後ろへ丸める場合があります。リズム側のコード解析にはイントロも使います。
0は自動判定のみで、リードがない区間を必ず自動認識できるという意味ではありません。
全区間で採用するリード候補がなければ休符を出力し、偽の音は追加しません。
この指定は曲ごとの入力であり、特定の曲の開始時刻を自動設定するものではありません。

### 音声から独立したリードの根拠を確認する（実験的）

分割生成時は「音声で独立したリードを確認（実験的）」が既定で有効です。
「リード開始」を0にしたままでも音声判定が働きます。

- ステレオを保持して音を読み込み、検出ノートの基音・倍音に対応する左右の
  エネルギー、位相差、倍音構成、発音前後の変化を調べます。
  ステレオの同じ声部では音程や押さえ方による音色差を過大評価しないようにします。
- 左右差成分が十分にある場合は、左右平均に加えて左右差でも音程検出を実行し、
  一致する候補を統合します。左右平均で打ち消される成分を候補から落とさないためです。
  左右差そのものをリードと決めつける処理ではありません。
  この場合、音程検出の実行回数が増え、解析時間がおおむね2倍になることがあります。
- コード打音と、繰り返し現れる音色・定位のまとまりを伴奏の基準候補にします。
  それと違う特徴があるだけでは採用せず、伴奏と同時に続く別声部の根拠を要求します。
- 根拠のあるノートだけを旋律追跡へ渡します。単なる音量差や一度のパン移動だけで
  リードを増やさないようにし、候補がなければ「リードを確認できず／休符」と表示します。
- モノラルは定位を使わず倍音・発音を比較します。同じ音色・定位の複数のギターや、
  単独のギターしかない区間では判断できず、本当のリードも落とすことがあります。
- 解析対象は音程検出と同じ音声です。Demucs使用時は分離後のチャンネルを使います。
  モノラル化された音声からステレオ情報を復元することはできません。
- TABには使用した方式と、音声根拠があった候補数を記載します。解析失敗時は明示して
  リードを保留します。音声判定を解除すると従来のノートだけの追跡へ戻せます。

これは学習済みのリード分類モデルでも、校正された存在確率でもありません。
伴奏の基準や別声部の推定を使った保守的なヒューリスティックです。別声部が歌や
鍵盤だった場合の誤認、伴奏とリードの役割の逆転、リードの取りこぼしがありえます。
「確認できない」と「実際に鳴っていない」は異なります。実曲での精度は未評価です。

検証用に、音程・役割が分かる2つの音源をプログラムで合成し、伴奏アルペジオのみ、
別定位の旋律を追加、モノラル化、音色差、単一音源のパン移動、無音を比較しています。
合成音での成功を、実際の楽曲での分離精度としては扱いません。
